# 개발일지 / 인수인계

두 명이 같은 레포에서 작업하므로, 일지는 레포 안(`docs/devlog/`)에 남겨 서로 pull 해서 보게 한다.
세션 시작 훅이 최근 일지의 "다음 할 일"을 자동으로 읽어준다.

## 1. 재료 모으기 (직접 추측하지 말 것)
- 작성자: `git config user.name`
- 오늘 커밋: `git log --since=midnight --author="$(git config user.name)" --oneline --all`
- 변경 규모: `git diff --stat <오늘 첫 커밋>^..HEAD`
- 열린 PR / 리뷰 요청: `gh pr list --author @me`, `gh pr list --search "review-requested:@me"`
- 이 대화에서 내린 결정, 막힌 부분

## 2. 파일 작성: `docs/devlog/YYYY-MM-DD-<작성자>.md`
같은 날 파일이 있으면 이어서 쓴다.

```markdown
# YYYY-MM-DD <작성자>

## 한 일
- 기능 단위로 2~5개, 반영 위치 링크 + 관련 PR/커밋 링크

## 결정한 것
- 무엇을, 왜 (대안이 있었다면 왜 버렸는지), 반영 위치 링크 — 나중에 면접/회고 때 쓸 수 있게

## 막힌 것 / 팀원 확인 필요
- @팀원 에게 묻거나 부탁할 것

## 다음 할 일
- [ ] 우선순위 순으로
```

### 반영 위치 링크
"한 일", "결정한 것"의 각 항목과 "막힌 것" 중 문서·코드에 걸린 항목에는 그 내용이 반영된 곳의 링크를 건다. 읽는 사람이 바로 해당 부분을 열어볼 수 있어야 한다.
- 경로는 일지 파일 기준 상대 경로로 쓴다. 예: `[DOMAIN.md 3-2 게임 애그리거트](../DOMAIN.md#3-2-게임-애그리거트)`, `[pr-gate.sh](../../.claude/hooks/pr-gate.sh)`
- 문서는 해당 절의 제목 앵커(`#제목`, GitHub 규칙: 영문 소문자, 공백은 `-`, 한글은 그대로, 마침표·괄호 등 특수문자 제거)까지 건다. 앵커는 실제 제목을 읽고 만든다. 추측하지 않는다. `.md`는 렌더 화면에서 `#L` 줄 링크가 동작하지 않으므로 줄 링크를 쓰지 않는다.
- 코드는 파일 링크에 줄 번호를 붙인다. 예: `[AnswerJudge.java#L12](../../core/src/main/java/.../AnswerJudge.java#L12)`. 커밋된 코드는 줄이 밀리지 않도록 커밋 해시 기준 링크(`https://github.com/<owner>/<repo>/blob/<hash>/<경로>#L12`)를 쓴다.
- 커밋·PR이 있으면 함께 건다. 커밋은 짧은 해시, PR은 `gh pr view --json url`로 얻은 URL.
- 미커밋 변경은 파일·절 링크만 건다(줄 번호 없이, 푸시 후 열린다).
- 링크할 곳이 없는 항목(순수 논의, 아직 반영 안 된 결정)은 링크 없이 "(미반영)"이라고 적는다.

## 3. 공유
- `docs: devlog YYYY-MM-DD` 로 커밋한다(PR 없이 main에 바로 올릴지 사용자에게 물어본다).
- 채팅(카톡/디스코드/슬랙)에 붙여넣을 3~5줄 요약을 대화에 출력한다: 한 일 한 줄, 팀원 확인 필요 사항, 내일 할 일.

## 주간 회고 (인자로 `week` 가 주어지면)
최근 7일 `docs/devlog/*.md` 를 모두 읽고 `docs/devlog/weekly/YYYY-Www.md` 로 두 사람 작업을 합쳐 정리한다: 완료 기능, 주요 결정, 남은 리스크, 다음 주 목표. 반영 위치 링크는 일지에서 그대로 옮기지 말고 `weekly/` 기준 상대 경로(한 단계 더 깊음)로 고쳐 쓴다.
