# 노래 정보 조회와 영상 선택 규칙

노래의 곡 정보를 Spotify에서 조회하고, YouTube에서 재생할 영상([음원](DOMAIN.md#3-5-콘텐츠-애그리거트))을 고르는 규칙이다. 최종 노래 목록을 만드는 크롤링·파싱 규칙은 [`MUSIC_PARSING_RULE.md`](MUSIC_PARSING_RULE.md)에 있다.

영화 스무고개의 OST 단서도 2장의 YouTube 영상 선택 규칙으로 고른다. 검색어는 `"{영화 제목} OST"`다.

이 규칙은 두 시점에 쓴다.

- **초기 데이터 곡을 출제할 때**: 초기 데이터에는 Spotify 정보와 음원이 없다. 곡이 많아 미리 한꺼번에 조회하면 API 호출이 막힐 수 있으므로, 출제할 곡에 정보가 없을 때 그때 조회해 저장한다.
- **데일리 크롤링이 새 곡을 추가할 때**: 정제와 중복 제거를 마친 곡을 바로 조회해 저장한다([크롤링 실행](DOMAIN.md#3-8-크롤링-실행-애그리거트)).

1. **Spotify**: 곡의 제목과 가수로 곡 정보(앨범, 발매일)를 조회해 저장한다. DB에 이미 있으면 조회하지 않고 그 정보를 쓴다.
2. **YouTube**: 곡의 재생 영상을 검색해 가장 적합한 영상 하나를 고르고 음원으로 저장한다. DB에 그 노래의 음원이 있으면 검색하지 않고 그 음원을 쓴다.

```
곡 선택 (출제할 때) 또는 새 곡 추가 (데일리 크롤링)
 └─ DB에 곡 정보 있음 → 그 정보 사용
    DB에 곡 정보 없음 → Spotify 조회 → 곡 정보 저장
 └─ DB에 음원 있음 → 그 음원 사용
    DB에 음원 없음 → YouTube 검색 → 우선순위에 따라 영상 1개 선택 → 음원으로 저장
```

- 곡 하나의 조회 실패가 전체 흐름을 막지 않게 한다.
    - 출제할 때 실패하면 그 곡 대신 다른 곡을 출제한다. 다른 곡으로 최대 3번까지 다시 시도한다.
    - 데일리 크롤링에서 Spotify 조회가 실패하거나 YouTube 영상을 찾지 못하면 곡은 추가하되, 오류 신고(`SPOTIFY_NOT_FOUND`, `AUDIO_NOT_FOUND`)를 남겨 검수가 필요한 노래로 둔다([오류 신고](DOMAIN.md#3-6-오류-신고-애그리거트)).

## 1. Spotify (곡 정보 조회)

### 1-1. 검색 요청

`GET /v1/search`

| 파라미터 | 값 |
|---|---|
| `market` | `KR` |
| `limit` | `5` |
| `offset` | `0` |
| `Accept-Language` 헤더 | `ko` (한국어 이름 우선 응답) |

### 1-2. 아티스트 결정

1. `artists[0].artist`로 `type=artist` 검색을 한다.
2. 결과 중 이름이 `artists[0]`의 `artist` 또는 `artist_sub`와 **정확히 일치**(대소문자·공백 무시)하는 아티스트가 있으면 그 아티스트의 id와 첫 번째 이미지를 쓴다.
3. 일치하는 결과가 없으면 `artists[0].artist_sub`로 한 번 더 검색해 같은 방법으로 찾는다.
4. 그래도 없으면 첫 번째 검색의 첫 번째 결과를 쓴다.
5. 화면에 보여 줄 아티스트 이름은 `artists`의 `artist`를 `, `로 이어 쓴다.

### 1-3. 트랙 결정

1. `title`로 `type=track` 검색을 한다. 결과가 없으면 `subtitle`로 다시 검색한다.
2. 결과 중 **앨범의 첫 번째 아티스트 id**가 1-2의 아티스트 id와 같은 첫 번째 트랙을 고른다.
3. 일치하는 트랙이 없으면 첫 번째 트랙을 쓰되, 다른 가수의 동명곡일 수 있으므로 경고를 남긴다.
4. 트랙 id, 이름과 앨범 id, 이름, 첫 번째 이미지, 발매일을 저장한다.

제목만으로 검색하면 흔한 제목은 상위 5개 안에 원곡이 없을 수 있다. 정확도가 중요하면 쿼리에 아티스트를 함께 넣는다(예: `track:{title} artist:{artists[0].artist}`).

### 1-4. 필터링

| 조건 | 규칙 |
|---|---|
| 발매 연도 | 최소 연도를 정했다면 `발매 연도 >= 최소 연도` |
| 발매일 형식 | Spotify 발매일은 `yyyy-MM-dd`, `yyyy-MM`, `yyyy` 중 하나로 온다. 앞 4자리로 연도를 읽어야 날짜가 덜 적힌 곡이 빠지지 않는다 |

### 1-5. 에러 처리

| 상황 | 처리 |
|---|---|
| 토큰 만료 (401) | 토큰을 갱신하고 **1회 재시도** |
| 요청 과다 (429) | `retry-after` 헤더 값만큼 기다린 뒤 재시도 |
| 응답 지연 | 출제할 때 Spotify·YouTube 호출은 **5초** 안에 응답이 없으면 실패로 본다 |
| 곡 하나의 조회 실패 | 출제할 때는 다른 곡을 출제하고(최대 3번 재시도), 데일리 크롤링에서는 오류 신고를 남긴 뒤 나머지 곡을 계속 처리 |

## 2. YouTube (재생 영상 선택)

### 2-1. 검색 요청

| 항목 | 값 |
|---|---|
| API | `https://youtubei.googleapis.com/youtubei/v1/search` (비공개 innertube API) |
| client | `ANDROID_VR`, clientVersion `1.60.19`, androidSdkVersion `32`, clientScreen `EMBED` |
| params | `EgIQAfABAQ==` (동영상 타입 필터) |
| query | `"{정제한 제목} {정제한 아티스트}"` |

비공개 API라서 client 값이나 응답 구조가 예고 없이 바뀔 수 있다.

### 2-2. 응답 파싱

- `contents.sectionListRenderer`의 **첫 번째 섹션**만 본다.
- 각 항목의 `compactVideoRenderer`에서 `videoId`, 제목(`title.runs`의 첫 번째), 길이(`lengthText.runs`의 첫 번째, `m:ss` 또는 `h:mm:ss`)를 꺼낸다.
- 고른 영상은 [음원](DOMAIN.md#3-5-콘텐츠-애그리거트)으로 저장하므로 다음도 함께 꺼낸다. 채널명(`longBylineText.runs`의 첫 번째), 조회수(`viewCountText.runs`의 첫 번째, 숫자만), 업로드 시기(`publishedTimeText.runs`의 첫 번째, `4 years ago` 같은 원문). 이 세 값은 응답에 없을 수 있다.
- 검색 순서대로 **상위 5개**만 후보로 쓴다.

### 2-3. 영상 우선순위

목표는 음원(AR)에 가장 가까운 영상을 고르는 것이다.

| 순위 | 조건 | 선택 방식 |
|---|---|---|
| 1 | 제목에 `가사` 또는 `lyrics`(대소문자 무시)가 들어간 영상이 있음 | 그중 **검색 순서상 첫 번째** 영상 (가사 영상은 대개 원곡 음원을 쓴다) |
| 2 | 가사 영상이 없음 | 제목에 `live`(대소문자 무시)가 **없는** 영상을 우선하고 그 안에서 **재생 시간이 가장 짧은** 영상 |
| 3 | 가사 영상이 없고 후보가 모두 live | 전체 중 **재생 시간이 가장 짧은** 영상 |

뮤직비디오의 인트로·아웃트로나 긴 편집본을 피하려고 재생 시간이 짧은 영상을 고른다.

| 후보 (제목, 길이) | 선택 |
|---|---|
| `일반 노래 3:30`, `노래 제목 가사 4:00`, `Live 버전 3:00` | `노래 제목 가사` |
| `Normal Song 1 4:00`, `Live Performance 2:30`, `Normal Song 2 3:20`, `Another Live 3:00` | `Normal Song 2` |
| `Live Performance 1 4:00`, `Live Performance 2 3:15`, `Live Performance 3 3:45` | `Live Performance 2` |

### 2-4. 구현할 때 주의할 점

- `live`도 단어 단위로 비교한다. 부분 문자열로 비교하면 제목에 `Deliver`, `Oliver`가 들어간 영상도 라이브로 판정된다.
- 검색 결과가 비었거나 응답 구조가 다를 수 있다. 출제할 때 호출은 5초 안에 응답이 없으면 실패로 본다. 출제할 때 실패하면 다른 곡으로 최대 3번까지 다시 시도하고, 데일리 크롤링에서 실패하면 `AUDIO_NOT_FOUND` 오류 신고를 남긴다.
