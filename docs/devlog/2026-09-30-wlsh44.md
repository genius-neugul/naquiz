## 결정한 것
- **단서는 힌트와 별개 엔티티**: 단서는 차례 참가자가 여는 영화 정보이고, 정답 힌트는 모든 단서가 열린 뒤 정답 형태를 보여준다. 공개 주체와 조건이 달라서 분리했다. 단서는 공개한 참가자 ID가 필수이고, 힌트에는 이 속성이 없다. → [3-2. 게임 애그리거트](../DOMAIN.md#3-2-게임-애그리거트)
- **같은 라운드에서 같은 단서는 한 번만 열 수 있다.** → [3-2. 게임 애그리거트](../DOMAIN.md#3-2-게임-애그리거트)
- **정답은 answer / subAnswer 두 속성**: 노래(title/subtitle)와 영화(한글/영문 제목) 모두 정답이 최대 두 개라서 별칭 엔티티는 과했다. → [3-3. 문제 애그리거트](../DOMAIN.md#3-3-문제-애그리거트)
- **정답 힌트의 기준 문자열은 answer** → [2. 유비쿼터스 언어](../DOMAIN.md#2-유비쿼터스-언어), [3-3. 문제 애그리거트](../DOMAIN.md#3-3-문제-애그리거트)
- **판정 규칙**: 입력값과 answer, subAnswer를 각각 정규화(공백 제거, 영문 소문자)해서 비교한다. 특수문자는 제거하지 않는다. → [2. 유비쿼터스 언어](../DOMAIN.md#2-유비쿼터스-언어), [3-3. 문제 애그리거트](../DOMAIN.md#3-3-문제-애그리거트)
- **정답 제출은 저장하지 않는다**: 판정만 한다. 그래서 애그리거트를 없앴다. 유비쿼터스 언어의 "정답 제출(Submission)" 용어는 판정 대상인 채팅 메시지를 부르는 말로 남겼다. → [2. 유비쿼터스 언어](../DOMAIN.md#2-유비쿼터스-언어)
- **투표에는 반대가 없다**: 찬성만 누를 수 있어 REJECTED 상태와 찬반 여부(agree)를 없애고 투표권(Ballot)을 투표 찬성(VoteApproval)으로 바꿨다. 통과하지 못하면 마감 시 EXPIRED. → [3-4. 투표 애그리거트](../DOMAIN.md#3-4-투표-애그리거트)
- **통과 기준은 투표 종류와 무관**: 스킵·힌트 모두 2명 이하면 전원 찬성, 3명 이상이면 과반수(찬성 수 × 2 > 참가자 수, 4명이면 3명) 찬성. 투표에 passThreshold 필드는 두지 않고 참가자 수로 계산한다. → [3-4. 투표 애그리거트](../DOMAIN.md#3-4-투표-애그리거트)
- **점수는 참가자 `roundScore` 하나로 둔다**: 게임 애그리거트의 점수 엔티티는 두지 않는다. 정답 1회당 1점, 게임 시작 시 0으로 초기화. → [3-1. 방 애그리거트](../DOMAIN.md#3-1-방-애그리거트)
- **정답 누락 신고는 `MISSING_ANSWER`**: 정답 별칭이 없어져서 `MISSING_ALIAS`에서 이름을 바꿨다. → [3-6. 오류 신고 애그리거트](../DOMAIN.md#3-6-오류-신고-애그리거트)
- **음원은 노래의 내부 엔티티**: YouTube에서 고른 영상 1개를 저장한다. 업로드 날짜는 상대 시간(`4 years ago`)만 오므로 원문과 조회 시각을 함께 둔다. 노래 루트의 `previewUrl`은 없앴다. 출제할 노래에 음원이 없으면 그때 YouTube에서 검색해 채운다. → [3-5. 콘텐츠 애그리거트](../DOMAIN.md#3-5-콘텐츠-애그리거트)
