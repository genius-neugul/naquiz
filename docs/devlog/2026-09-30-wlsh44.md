## 결정한 것
- **단서는 힌트와 별개 엔티티**: 단서는 차례 참가자가 여는 영화 정보이고, 정답 힌트는 모든 단서가 열린 뒤 정답 형태를 보여준다. 공개 주체와 조건이 달라서 분리했다. 단서는 공개한 참가자 ID가 필수이고, 힌트에는 이 속성이 없다. → [3-2. 게임 애그리거트](../DOMAIN.md#3-2-게임-애그리거트)
- **관리자 페이지 도메인**: 관리자·크롤링 실행 애그리거트, 문제 검수 상태, 오류 신고 처리자, 힌트 통계 조회 모델을 추가했다. 데일리 크롤링은 노래만 하고, 새 문제는 승인 전 출제하지 않는다. 초기 데이터로 적재한 문제는 승인 상태로 시작한다. 정답은 검수 상태와 관계없이 고칠 수 있고, 정답 오류 신고에는 신고자가 올바른 정답(`suggestedAnswer`)을 적을 수 있다. 힌트 통계는 정답 힌트·단서를 포함하고 자동 공개 힌트는 뺀다. → [3-7. 관리자](../DOMAIN.md#3-7-관리자-애그리거트), [3-8. 크롤링 실행](../DOMAIN.md#3-8-크롤링-실행-애그리거트), [3-10. 힌트 통계](../DOMAIN.md#3-10-힌트-통계-백오피스-조회-모델)
- **영화 스무고개 단서에서 OST를 뺐다**: 영화 OST는 YouTube에서 알맞은 음원을 찾기 어려워서 우선 제외한다. 영화 애그리거트의 `ost` 필드도 지웠다. → [3-2. 게임 애그리거트](../DOMAIN.md#3-2-게임-애그리거트)
- **영화 스무고개 단서에서 스틸컷을 뺐다**: 스틸컷은 스틸컷 영화 맞추기에서만 쓴다. → [3-2. 게임 애그리거트](../DOMAIN.md#3-2-게임-애그리거트)
- **같은 라운드에서 같은 단서는 한 번만 열 수 있다.** → [3-2. 게임 애그리거트](../DOMAIN.md#3-2-게임-애그리거트)
- **정답은 answer / subAnswer 두 속성**: 노래(title/subtitle)와 영화(한글/영문 제목) 모두 정답이 최대 두 개라서 별칭 엔티티는 과했다. → [3-3. 문제 애그리거트](../DOMAIN.md#3-3-문제-애그리거트)
- **정답 힌트의 기준 문자열은 answer** → [2. 유비쿼터스 언어](../DOMAIN.md#2-유비쿼터스-언어), [3-3. 문제 애그리거트](../DOMAIN.md#3-3-문제-애그리거트)
- **판정 규칙**: 입력값과 answer, subAnswer를 각각 정규화(공백 제거, 영문 소문자)해서 비교한다. 특수문자는 제거하지 않는다. → [2. 유비쿼터스 언어](../DOMAIN.md#2-유비쿼터스-언어), [3-3. 문제 애그리거트](../DOMAIN.md#3-3-문제-애그리거트)
- **정답 제출은 저장하지 않는다**: 판정만 한다. 그래서 애그리거트를 없앴다. 유비쿼터스 언어의 "정답 제출(Submission)" 용어는 판정 대상인 채팅 메시지를 부르는 말로 남겼다. → [2. 유비쿼터스 언어](../DOMAIN.md#2-유비쿼터스-언어)
- **투표에는 반대가 없다**: 찬성만 누를 수 있어 REJECTED 상태와 찬반 여부(agree)를 없애고 투표권(Ballot)을 투표 찬성(VoteApproval)으로 바꿨다. 투표 시간 제한은 없고, 통과하기 전에 라운드가 끝나면 EXPIRED. → [3-4. 투표 애그리거트](../DOMAIN.md#3-4-투표-애그리거트)
- **통과 기준은 투표 종류와 무관**: 스킵·힌트 모두 2명 이하면 전원 찬성, 3명 이상이면 과반수(찬성 수 × 2 > 참가자 수, 4명이면 3명) 찬성. 투표에 passThreshold 필드는 두지 않고 참가자 수로 계산한다. → [3-4. 투표 애그리거트](../DOMAIN.md#3-4-투표-애그리거트)
- **점수는 참가자 `roundScore` 하나로 둔다**: 게임 애그리거트의 점수 엔티티는 두지 않는다. 정답 1회당 1점, 게임 시작 시 0으로 초기화. → [3-1. 방 애그리거트](../DOMAIN.md#3-1-방-애그리거트)
- **오류 신고 유형**: `WRONG_ANSWER`(정답 오류), `WRONG_HINT`(힌트 오류), `WRONG_AUDIO`(다른 곡 영상), `NOT_ORIGINAL_AUDIO`(MV·라이브 등 원곡 음원 아님), `SPOTIFY_NOT_FOUND`, `AUDIO_NOT_FOUND`(데일리 크롤링 전용), `OTHER`. 신고 출처(참가자/데일리 크롤링)를 구분한다. → [3-6. 오류 신고 애그리거트](../DOMAIN.md#3-6-오류-신고-애그리거트)
- **미정 사항 확정**: 방 최대 10명, 초대 코드 숫자·알파벳 6자리, 방장 위임 없음(방장이 나가면 방 종료), 재접속 불가, 목표 점수는 방장이 최대 50점까지 설정, 문제를 다 쓰면 다시 출제해 반드시 승자가 나옴, 라운드·투표 시간 제한 없음, 투표 인원은 접속 중인 참가자, 출제는 완전 무작위, 첫 관리자 계정은 DB 초기 세팅, 관리자 로그인은 JWT, 음원·Spotify 정보 오류는 관리자가 직접 입력, 스무고개 차례는 라운드마다, 시놉시스 제목은 `○○○`로 가림. 방장이 나가 끝난 게임은 승자 없이 FINISHED이고 방은 CLOSED, 정상 종료 후 방은 WAITING으로 돌아간다. 참가자가 나가면 진행 중인 투표를 줄어든 인원으로 다시 판정하고 스무고개 차례는 건너뛴다. 문제를 다 쓰면 매번 무작위로 다시 뽑는다. 투표 발의자는 자동 찬성, `currentTurnOrderIndex`는 Integer, 출제할 때 외부 API 타임아웃은 5초. 출제할 때 조회에 실패하면 최대 3번 다시 조회하고, 모두 실패하면 다음 곡을 출제한다. 데일리 크롤링은 매일 새벽 4시에 돌린다. 이로써 DOMAIN.md 미정 사항은 모두 정했다. → [4. 미정 사항](../DOMAIN.md#4-미정-사항)
- **데일리 크롤링은 끝까지 처리**: 정제 → 이미 있는 곡 제외 → Spotify 조회 → YouTube 음원 저장 → 검수 대기 문제까지 한 번에 한다. Spotify·YouTube 조회에 실패한 곡은 추가하되 오류 신고를 남겨 검수가 필요한 노래로 둔다. → [3-8. 크롤링 실행](../DOMAIN.md#3-8-크롤링-실행-애그리거트)
- **초기 데이터는 출제할 때 조회**: 초기 곡이 많아 Spotify·YouTube를 미리 한꺼번에 호출하면 막힐 수 있어서, 출제할 곡에 정보가 없을 때 조회해 저장한다. Spotify 인기도 필터와 인기도 기준 곡 선택은 쓰지 않는다. iTunes도 쓰지 않는다. → [노래 정보 조회와 영상 선택 규칙](../MUSIC_SELECTION_RULE.md)
- **음원은 노래의 내부 엔티티**: YouTube에서 고른 영상 1개를 저장한다. 업로드 날짜는 상대 시간(`4 years ago`)만 오므로 원문과 조회 시각을 함께 둔다. 노래 루트의 `previewUrl`은 없앴다. 출제할 노래에 음원이 없으면 그때 YouTube에서 검색해 채운다. → [3-5. 콘텐츠 애그리거트](../DOMAIN.md#3-5-콘텐츠-애그리거트)
