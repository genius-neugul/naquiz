## 결정한 것
- **저장 위치는 통계 필요 여부로 나눈다**: 백오피스 통계(문제·힌트·투표)에 쓰이거나 원래 영속 데이터인 모델은 JPA 엔티티로 DB에 둔다. 방·참가자는 통계에 쓰이지 않아 JPA 없는 순수 객체로 서버 메모리에 둔다. 투표는 "어떤 투표를 많이 했는지" 볼 수 있어 DB에 남긴다. 전부 DB에 두는 안은 비회원·재접속 없는 참가자까지 저장하게 돼서 버렸다. → [Infra 작성 규칙](../../core/docs/ARCHITECTURE.md#infra-작성-규칙)
  - 참가자를 저장하지 않으므로 승자·정답자·단서를 연 참가자·투표 찬성의 참가자 ID는 FK 없는 Long 값이다.
  - 라운드의 차례 필드(turnOrder, currentTurnOrderIndex, turnDeadline)는 진행 중에만 쓰므로 `@Transient`다.
- **로컬은 H2, local-dev는 MySQL(docker-compose)** → [`core/CLAUDE.md` 자주 쓰는 명령](../../core/CLAUDE.md#자주-쓰는-명령)
- **모든 모듈의 패키지는 `geniusneugul.project.core`**: 앱 클래스가 같은 패키지에 있어 core-domain 엔티티·빈을 별도 스캔 설정 없이 찾는다. → [모듈 구조](../../core/docs/ARCHITECTURE.md#모듈-구조)
- **DB 설정은 core-domain `domain.yml` 한 벌**: 앱은 `spring.config.import`로 가져오고 앱 이름·포트만 따로 둔다. 앱마다 같은 datasource 설정을 복사하지 않으려는 것이다.
- **설정 파일은 yml로 쓴다.** → [`core/CLAUDE.md` 작업 규칙](../../core/CLAUDE.md#작업-규칙)
- **통합 테스트는 앱 모듈에만 둔다**: core-domain은 `@SpringBootApplication`이 없는 라이브러리라 단위 테스트만 둔다. core-domain에 테스트 전용 Boot 앱을 두는 안은 버렸다. 그래서 `IntegrationTestSupport`가 세 앱에 같은 내용으로 있다. → [Spring Context 재사용](../../core/docs/TEST.md#spring-context-재사용)
- **앱 분리는 모노레포로**: 게임 앱과 백오피스 앱은 따로 배포할 수 있게 나누고, 토큰·컴포넌트·도메인 함수는 `packages/`로 공유한다. 두 디렉터리로 나눠 복사하는 방식은 수정할 때 둘이 어긋나기 쉬워서, 한 앱에 `/admin` 라우트를 두는 방식은 백오피스 접근 경계가 흐려져서 버렸다. → [`front/CLAUDE.md` 디렉터리 구조](../../front/CLAUDE.md#디렉터리-구조)
- **게임 상태는 GameClient 인터페이스 뒤에 둔다**: 디자인 프로토타입은 봇·타이머가 컴포넌트 안에 있었다. 서버가 생기면 구현만 갈아끼우도록 Mock 어댑터로 옮겼다. → [`front/CLAUDE.md` 작업 규칙](../../front/CLAUDE.md#작업-규칙)
- **디자인과 docs/가 다르면 문서를 따른다**: 화면 레이아웃·스타일은 디자인, 규칙·문구는 DOMAIN.md를 따랐다.
  - 정규화는 공백 제거와 소문자 변환만 한다(특수문자 유지). 정답 후보는 answer와 subAnswer다. → [3-3. 문제 애그리거트](../DOMAIN.md#3-3-문제-애그리거트)
  - 목표 점수는 1~50점, 방 최대 인원은 10명이다.
  - 투표 시간 제한은 없고, 노래 힌트 투표는 종류별로 동시에 연다. → [3-4. 투표 애그리거트](../DOMAIN.md#3-4-투표-애그리거트)
  - 영문 부분 공개는 단어 글자 수 ÷ 3(반올림)만큼이다. 스무고개 차례는 라운드마다 무작위이고 10초가 지나면 패스한다. → [3-2. 게임 애그리거트](../DOMAIN.md#3-2-게임-애그리거트)
  - 신고 유형은 DOMAIN 코드를 쓰고, 정답 오류는 올바른 정답을 입력받는다. → [3-6. 오류 신고 애그리거트](../DOMAIN.md#3-6-오류-신고-애그리거트)
  - 디자인에 있던 시안 A/B 전환, 인물 스무고개 카드, 백오피스 정답률 기반 출제(MVP 범위 밖)는 뺐다. "로비"는 "대기실"로 바꿨다.
- **`front/.npmrc`에 `legacy-peer-deps=true`**: npm 10.9가 vite 8의 optional peer(`@vitejs/devtools` → vitest) 순환에서 `edgesOut` 오류로 설치에 실패했다. vite 7로 낮춰도 vitest가 vite 8을 끌어와 같은 오류가 났다. 필요한 peer는 package.json에 직접 적었다. → [`front/CLAUDE.md` 기술 스택](../../front/CLAUDE.md#기술-스택)
