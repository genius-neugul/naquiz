## 결정한 것
- **저장 위치는 통계 필요 여부로 나눈다**: 백오피스 통계(문제·힌트·투표)에 쓰이거나 원래 영속 데이터인 모델은 JPA 엔티티로 DB에 둔다. 방·참가자는 통계에 쓰이지 않아 JPA 없는 순수 객체로 서버 메모리에 둔다. 투표는 "어떤 투표를 많이 했는지" 볼 수 있어 DB에 남긴다. 전부 DB에 두는 안은 비회원·재접속 없는 참가자까지 저장하게 돼서 버렸다. → [Infra 작성 규칙](../../core/docs/ARCHITECTURE.md#infra-작성-규칙)
  - 참가자를 저장하지 않으므로 승자·정답자·단서를 연 참가자·투표 찬성의 참가자 ID는 FK 없는 Long 값이다.
  - 라운드의 차례 필드(turnOrder, currentTurnOrderIndex, turnDeadline)는 진행 중에만 쓰므로 `@Transient`다.
- **로컬은 H2, local-dev는 MySQL(docker-compose)** → [`core/CLAUDE.md` 자주 쓰는 명령](../../core/CLAUDE.md#자주-쓰는-명령)
- **모든 모듈의 패키지는 `geniusneugul.project.core`**: 앱 클래스가 같은 패키지에 있어 core-domain 엔티티·빈을 별도 스캔 설정 없이 찾는다. → [모듈 구조](../../core/docs/ARCHITECTURE.md#모듈-구조)
- **DB 설정은 core-domain `domain.yml` 한 벌**: 앱은 `spring.config.import`로 가져오고 앱 이름·포트만 따로 둔다. 앱마다 같은 datasource 설정을 복사하지 않으려는 것이다.
- **설정 파일은 yml로 쓴다.** → [`core/CLAUDE.md` 작업 규칙](../../core/CLAUDE.md#작업-규칙)
- **통합 테스트는 앱 모듈에만 둔다**: core-domain은 `@SpringBootApplication`이 없는 라이브러리라 단위 테스트만 둔다. core-domain에 테스트 전용 Boot 앱을 두는 안은 버렸다. 그래서 `IntegrationTestSupport`가 세 앱에 같은 내용으로 있다. → [Spring Context 재사용](../../core/docs/TEST.md#spring-context-재사용)
