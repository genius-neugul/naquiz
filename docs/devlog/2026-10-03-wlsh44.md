## 결정한 것
- **참가자 식별은 연결 단위**: 핸드셰이크 때 연결마다 UUID Principal을 붙여 참가자 토큰으로 쓴다. 재접속이 없고 끊기면 퇴장이라는 규칙과 맞고, 토큰 발급·검증이 필요 없다. 클라이언트가 토큰을 들고 다니는 방식은 재접속이 없어 이점이 없어서 버렸다. → [ConnectionHandshakeHandler](https://github.com/genius-neugul/naquiz/blob/947442c/core/game-api/src/main/java/geniusneugul/project/core/common/presentation/ConnectionHandshakeHandler.java#L17), [DOMAIN.md 3-1](../DOMAIN.md#3-1-방-애그리거트)
- **닉네임은 겹쳐도 되고 `#태그`로 구분**: 태그는 방 안 입장 순서 번호(방장 #1), 나간 사람 번호는 다시 쓰지 않는다. 중복 닉네임을 거절하는 대신 택했다. 무작위 4자리 태그는 입장 순서가 안 보여서, 빈 번호 재사용은 채팅 기록에서 누가 누군지 헷갈려서 버렸다. → [DOMAIN.md 3-1](../DOMAIN.md#3-1-방-애그리거트), [기획.md](../기획.md)
- **게임 중(PLAYING) 방에는 입장 불가**: 점수·차례·투표 기준 인원이 게임 도중에 바뀌지 않게. 초대 코드는 서버가 공백을 빼고 대문자로 받는다.
- **동시성은 방 단위 락**: 처음엔 `Room` 메서드마다 `synchronized`였는데, 메서드 사이가 비어 "확인 후 추가"(인원 상한)를 지키지 못한다. 확인·변경·색인 갱신·결과 스냅샷을 한 락에 넣고, 락 안에서 I/O는 하지 않는다. Redis 원자 연산은 서버 한 대인 지금은 이점이 없고 규칙이 Lua로 흩어져서, 방별 순차 실행(큐)은 비동기 전환 비용이 커서 게임 진행 때 다시 보기로 했다. → [ARCHITECTURE.md 동시성](../../core/docs/ARCHITECTURE.md#동시성)
- **불변식 위반은 표준 예외**: 사용자가 일으킬 수 없는 코드 오류(ID 두 번 부여 등)는 `IllegalStateException`으로 던지고 문구만 `ErrorCode`에 둔다. 버그를 warn에 묻지 않고 error로 드러내려는 것이다. `BusinessException`으로 통일하는 안은 버렸다. → [EXCEPTION.md 불변식 위반](../../core/docs/EXCEPTION.md#불변식-위반)
- **game-api 이미지**: 의존성 단계를 분리하고 Spring Boot 레이어 jar로 풀었다. 의존성을 이미지 레이어에 굽는 안은 재빌드가 6초→12~15초로 느려져서, 의존성은 캐시 마운트에 두는 쪽으로 정했다. 코드만 바꾸면 실행 이미지에서 바뀌는 레이어가 57.8MB→93.5kB. → [Dockerfile](../../core/game-api/Dockerfile)
- **채팅 규칙**: 1~100자(앞뒤 공백 제외), 저장하지 않아 들어온 뒤의 채팅만 보인다, 도배 방지는 아직 없다. 정답 판정은 게임 진행을 만들 때 같은 경로에 붙인다. → [기획.md](../기획.md)
- **채팅은 방 토픽에 합친다**: 처음엔 `/topic/rooms/{id}/chat`으로 나눴는데, 게임 이벤트(정답·힌트·투표)가 채팅 흐름 사이에 끼므로 한 토픽·한 핸들러로 받는 쪽이 단순해서 합쳤다. 순서는 `setPreservePublishOrder(true)`로 한 연결 단위로 지킨다(토픽을 나눠도 같음). → [WebSocketConfig](https://github.com/genius-neugul/naquiz/blob/68c7d39/core/game-api/src/main/java/geniusneugul/project/core/common/config/WebSocketConfig.java#L36)
- **상태를 바꾸지 않는 조회는 락 없이**: 채팅 보낸 사람 확인은 `RoomMemberReader.read`가 락 없이 읽고, 확인 후 변경하는 흐름(정답 제출)용 `readWithLock`을 따로 뒀다. 참가자 목록이 `ArrayList`라 입장·퇴장과 정확히 겹치면 드물게 `ConcurrentModificationException`이 날 수 있음을 알고 택했다(`CopyOnWriteArrayList`로 바꾸는 안은 보류). → [RoomMemberReader](https://github.com/genius-neugul/naquiz/blob/68c7d39/core/core-domain/src/main/java/geniusneugul/project/core/room/implement/RoomMemberReader.java#L22), [ARCHITECTURE.md 동시성](../../core/docs/ARCHITECTURE.md#동시성)
