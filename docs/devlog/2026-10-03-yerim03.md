## 결정한 것
- **초기 데이터를 SQL 파일로 넣는다**: 어제는 Spring 코드로 JSON을 읽어 적재하는 방식을 골랐다(SQL은 엔티티를 바꾸면 깨진다는 이유). 오늘은 JSON을 한 번 SQL로 만들어 두고 시작할 때 넣는 쪽으로 바꿨다. 적재 코드와 별도 실행 명령이 없어지고, H2로 띄워도 데이터가 바로 있다. 변환 스크립트는 저장소에 두지 않았다. JSON이 바뀌면 SQL을 다시 만들어야 하고, 엔티티 컬럼이 바뀌면 SQL도 고쳐야 한다. → [initial-data.sql](../../core/core-domain/src/main/resources/sql/initial-data.sql)
- **H2·MySQL 모두 시작할 때 넣되, `song`이 비어 있을 때만 넣는다**:
  - 처음에는 매번 `INSERT IGNORE`로 실행했다. 그러면 MySQL에서 지운 콘텐츠나 목록에서 뺀 항목이 재시작할 때 같은 ID로 되살아나서 바꿨다(코드 리뷰 지적).
  - `ddl-auto`를 `create`로 바꾸는 방법은 시작할 때마다 게임·문제·관리자 데이터까지 지워서 버렸다.
  - MySQL만 수동으로 넣는 방법은 자동 적재 요구와 맞지 않아서 버렸다.
  - SQL 안의 `INSERT IGNORE`는 빈 DB에 여러 앱이 동시에 처음 뜰 때를 위한 안전장치로 남겼다.
  - → [InitialDataLoader.java#L34](https://github.com/genius-neugul/naquiz/blob/34e4a2cf9ce0e577e34662e6523bbd6050342b1c/core/core-domain/src/main/java/geniusneugul/project/core/common/infra/initialdata/InitialDataLoader.java#L34)
- **ID는 JSON 순서로 직접 넣는다**: H2를 `MODE=MySQL`로 쓰면 직접 넣은 ID 다음 번호부터 자동 생성 ID가 이어져서, 나중에 앱이 저장하는 데이터와 겹치지 않는다(MODE 없는 H2는 충돌). 백슬래시는 MySQL·H2가 다르게 읽어서 `CONCAT(..., CHAR(92), ...)`로 썼다. → [initial-data.sql](../../core/core-domain/src/main/resources/sql/initial-data.sql)
- **문제는 콘텐츠를 적재할 때 미리 만든다**:
  - 출제할 때 만드는 방법은 버렸다. DOMAIN.md의 검수 상태(PENDING/APPROVED), 중복 출제 규칙, 오류 신고의 `questionId`가 모두 문제가 미리 있어야 성립하기 때문이다.
  - 문제는 JSON 변환과 무관하게 SQL 안의 `INSERT IGNORE … SELECT`로 콘텐츠 테이블을 읽어 만든다. 행을 하나씩 쓰지 않아 파일이 거의 커지지 않고, 정답이 콘텐츠 제목과 어긋날 수 없다.
  - ID는 고정했다. 노래는 `song.id`, 스무고개는 `100000 + movie.id`, 스틸컷은 `200000 + movie.id`다. 여러 앱이 동시에 처음 떠도 같은 문제를 건너뛴다.
  - 스틸컷이 없는 영화 9편은 스틸컷 문제를 만들지 않는다.
  - 초기 데이터 문제는 검수자·검수 시각을 비운 채 승인 상태로 시작한다(DOMAIN.md 보완).
  - → [initial-data.sql#L72648](https://github.com/genius-neugul/naquiz/blob/1f5827bad23b6f8d59353dabc1efb0fa29ec7ef8/core/core-domain/src/main/resources/sql/initial-data.sql#L72648), [core/CLAUDE.md 작업 규칙](../../core/CLAUDE.md#작업-규칙)
- **테스트에서는 초기 데이터를 끈다**: 통합 테스트는 매 테스트 전에 테이블을 비우므로 넣을 이유가 없다. 테스트 리소스에 `application.yml`을 두면 메인 설정을 덮어써서, 세 `IntegrationTestSupport`에 `naquiz.initial-data.enabled=false`를 넣었다. → [core/CLAUDE.md 작업 규칙](../../core/CLAUDE.md#작업-규칙)
- **정답 힌트는 4단계로 나누고 노래·영화 스무고개가 함께 쓴다**: 처음 안은 3단계(1단계에 띄어쓰기·숫자·특수문자까지 보여주고, 2단계 초성, 3단계부터 한 글자씩)였다. 1단계를 띄어쓰기도 없이 가장 어렵게 시작하고 싶어서 4단계로 나눴다. 영화 스무고개의 기존 단계(글자 수 → 초성 → 한 글자씩)는 노래와 달라 서버·프론트가 규칙을 두 벌 가져야 해서 하나로 합쳤다. 영문은 초성 개념이 없어서 3단계에서 단어마다 1/3을 먼저 보여준다. → [DOMAIN.md 3-2. 게임 애그리거트](../DOMAIN.md#3-2-게임-애그리거트)
- **새 정보가 없는 단계는 건너뛴다**: 띄어쓰기·숫자·특수문자가 없는 정답(국제시장)은 2단계가 1단계와 같아서 건너뛴다. `1987`, `OK`처럼 공개하면 정답 전체가 드러나는 단계도 건너뛴다. 4단계는 가려진 자리가 1개 남으면 멈춘다. → [AnswerHint.java#L37](https://github.com/genius-neugul/naquiz/blob/54135ba/core/core-domain/src/main/java/geniusneugul/project/core/game/domain/AnswerHint.java#L37)
- **공개 내용은 공개하는 순간 만들어 저장한다**: 라운드 시작 때 미리 만들거나 문제에 저장하는 안도 있었지만, DOMAIN.md의 "공개 시점에 확정해 저장" 규칙을 그대로 따랐다. 4단계는 직전 공개 내용과 자리별로 비교해 다음 글자를 고르므로, 마스킹 문자를 코드 포인트 하나인 `⚫`(U+26AB)로 정했다.
- **영화 스무고개 정답 힌트는 투표 없이 차례 참가자가 연다**: 단서와 같은 방식(10초 안에 안 열면 패스)이다. 스틸컷은 마지막 스틸컷 10초 뒤 자동으로 연다.
- **`AnswerHintRevealer`는 라운드·문제 객체 대신 `(Game, roundNo, answer)`를 받는다**: `Round`·`Question`을 만들 생성자가 아직 없고, 필요한 값은 이것뿐이다. 같은 이유로 테스트용 `GameFixture`는 리플렉션으로 `Game`을 만든다. 게임 시작 로직이 생기면 바꾼다.
