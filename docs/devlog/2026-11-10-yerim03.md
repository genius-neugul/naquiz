## 결정한 것
- **"단계" 대신 "공개 우선순위"로 부른다**
  - 숫자·한글이 없으면 건너뛰고 부분 공개는 반복되므로, "1단계·2단계"라는 번호가 실제 화면 순서와 맞지 않는다.
- **글자마다 상태를 두고 메모리에 저장한다**
  - 전에는 직전 공개 문자열과 정답을 자리별로 비교해 다음 공개를 계산했다. 글자 상태를 직접 들고 있으면 비교와 길이 검사가 필요 없다.
  - 공개 상태는 진행 중에만 필요하고, 다른 게임(스틸컷)도 DB에 남기지 않는다. 통계용 저장은 백오피스를 만들 때 정한다.
- **`revealed`는 원래 글자가 그대로 보일 때만 참이다**
  - 초성만 보이는 한글은 완전히 공개된 것이 아니므로 부분 공개 대상에 들어간다.
- **우선순위 순서는 enum 선언 순서로 정한다(숫자 필드를 두지 않는다)**
  - 공개 클래스를 빈으로 나눠도 순서는 도메인 개념이므로 `AnswerHintPriority` 한 곳에 둔다. 빈마다 숫자나 `@Order`를 주면 순서가 여러 파일에 흩어진다.
- **공개 클래스를 implement에 두고, 다음 우선순위 고르기는 `AnswerHintRevealer`가 맡는다**
  - 힌트를 실제로 만드는 코드라 implement에 둔다. domain은 implement를 참조할 수 없어서 고르는 반복문도 implement로 옮겼다.
  - 고르는 역할만 맡는 빈을 따로 두는 안도 있었지만, 이름이 비슷한 클래스가 셋이 되어 합쳤다.
- **유니코드 숫자 대신 문자 리터럴을 쓴다** (`'가'`~`'힣'`, `'a'`, `'0'`, `"⚫"`)
