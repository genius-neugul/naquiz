# Windows에서 프로젝트 훅이 실행되지 않음

- 날짜: 2026-10-01
- 관련 파일: `.claude/settings.json`, `.claude/hooks/`

## 증상

Windows에서 Claude Code를 열면 세션 시작 브리핑이 Claude에게 들어오지 않았다. 세션 기록(`~/.claude/projects/<프로젝트>/<세션>.jsonl`)에는 훅마다 다음 에러가 남았다.

```
"hookName":"SessionStart:startup", "stderr":"Failed to run: EFTYPE: inappropriate file type or format, uv_spawn"
"hookName":"PreToolUse:Bash",      "stderr":"Failed to run: EFTYPE: inappropriate file type or format, uv_spawn"
```

이 에러는 non-blocking이라 작업은 계속 진행된다. 그래서 PR 게이트와 테스트 context 가드도 실행되지 않은 채 넘어갔다. 같은 스크립트를 `bash`로 직접 실행하면 정상적으로 동작했다.

## 원인

- `settings.json`의 훅마다 `"args": []`가 있었다. Claude Code는 `args`가 있으면 셸 없이 `command`를 직접 실행한다(exec form, [hooks 문서](https://code.claude.com/docs/en/hooks.md)).
- `command`는 `.sh`·`.py` 파일 경로였다. macOS는 첫 줄의 shebang(`#!/usr/bin/env bash`)을 보고 실행하지만, Windows는 shebang을 읽지 못해서 파일을 실행할 수 없다.

## 해결

- 모든 훅에서 `args`를 빼고 인터프리터를 앞에 적었다.
  - `bash "$CLAUDE_PROJECT_DIR/.claude/hooks/session-brief.sh"`
  - `bash "$CLAUDE_PROJECT_DIR/.claude/hooks/pr-gate.sh"`
  - `python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/test-context-guard.py"`
- `args`가 없으면 셸로 실행된다(macOS는 `sh -c`, Windows는 Git Bash). `$CLAUDE_PROJECT_DIR`는 환경 변수로 전달된다.
- Windows 설정 안내(jq·gh 설치, `python3`)와 훅 등록 규칙을 `.claude/README.md`에 적었다.

### 참고: Windows PC에서 따로 맞출 것

- python.org 설치판은 `python3` 명령을 만들지 않는다. `WindowsApps/python3.exe`는 Microsoft Store 리다이렉터라 실행하면 exit 49로 끝난다. Store 판 Python을 설치해 `python3`를 맞춘다.
- Windows의 Python은 표준 입출력을 시스템 코드 페이지(cp949)로 처리한다. 그래서 테스트 context 가드의 한글 차단 사유가 UTF-8이 아닌 바이트로 나간다. 사용자 환경 변수 `PYTHONUTF8=1`로 맞춘다. 저장소는 바꾸지 않았다.

## 확인

훅 명령을 등록된 문자열 그대로 `bash -c`로 실행하고 샘플 입력을 넣었다(Windows).

| 훅 | 입력 | 결과 |
|---|---|---|
| session-brief | `{}` | "## 현재 작업 맥락" 출력 |
| pr-gate | Bash `ls` | 스크립트 실행됨(EFTYPE 없음). jq가 없는 PC라 `jq: command not found` |
| test-context-guard | `core/src/test/.../FooTest.java`에 `@DirtiesContext` | deny JSON (`python`으로 실행) |
| test-context-guard | 위반 없는 내용 / `support/` 경로 | 출력 없음 |
